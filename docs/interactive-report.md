# Интерактивность и автономный HTML

Сборка: `node scripts/build-standalone.mjs`. Результаты: корневые index.html и portfolio.html, одинаковые автономные файлы. CSS, JavaScript и favicon встроены; концепции доступны внутри документа. Внешних библиотек, шрифтов и загрузок нет. Telegram остаётся внешней ссылкой.

Форма — только локальная демонстрация. Изначально fieldset disabled; обработчик отмены отправки устанавливается до включения полей. Проверяются обязательность, email и длины полей; текст обрезается по краям. Успех не означает доставку сообщения. Сетевые запросы и хранение данных отсутствуют.

Счётчики отражают структуру сайта: 3 направления, 4 этапа, 3 концепта. Значения видны без JS, анимация запускается один раз при появлении. При reduced motion сразу показывается итог. Кнопка наверх появляется после 500 px, меню поддерживает aria-expanded, Escape и возврат фокуса.

Проверено: node --check public/app.js; node --check scripts/build-standalone.mjs; node --test (6 тестов). Регрессионная проверка исключает сетевые и storage API в клиентском JS, корневые ресурсы и внешние script/stylesheets в автономном файле.

Исходные адаптивные границы: 600/601 px для мобильного меню, 900/901 px для движения hero; добавленные поля занимают ширину контейнера, статистика переносится. Реальные мобильные браузеры, клавиатурная навигация и визуальный результат анимаций вручную не проверены; source-проверка не заменяет такую QA.

Дополнительная браузерная проверка: локальная страница открылась в IAB на http://127.0.0.1:4173. В снимке DOM присутствуют hamburger «Открыть меню», три счётчика, поля Имя/Email/Сообщение и демо-кнопка. При заданной ширине 375 px измерено innerWidth=375, documentElement.scrollWidth=360 (горизонтальное переполнение не обнаружено в этом замере). Последовательные клики мобильного сценария завершались тайм-аутом селектора; успешный сценарий меню/формы и реальное устройство не подтверждены. Открытие file:// запрещено политикой встроенного браузера, поэтому автономный файл проверен сборкой и тестами, без браузерной file-проверки.

Мессенджеры: файл не требует соседних ресурсов, но конкретный мессенджер может блокировать HTML/JavaScript или показывать только предпросмотр. Гарантировать открытие одним нажатием из любого мессенджера невозможно. В таком случае нужно скачать HTML и открыть поддерживающим браузером; для одинакового перехода по нажатию нужна опубликованная HTTPS-ссылка.
